02 / Reliable data flow

1チャンクの旅

ネットワーク切断やプロセス再起動を前提に、各境界をIDと永続状態でつなぎます。

録音から翻訳表示までの基本経路

Capture5秒の音声チャンクを生成。session_id と seq を付与。
Buffer locallyまず IndexedDB に保存。送信前のブラウザ終了にも備える。
UploadWebSocketで送信。切断後は last_acked_seq から再開。
Persist + ACKサーバー側の音声保存とDB記録が完了した時だけACK。
ASR + Assemble未完結チャンクを結合し、暫定／確定発話を分離。
Translate直近6発話の原文・訳文を参照し、確定発話だけをFIFO処理。
Publish保存後にイベント配信。再接続時はcursor以降を再取得。
At-least-once delivery重複受信を許し、DBの一意制約で安全に排除。
Ordered final output翻訳の完了順ではなく utterance の順番で表示。
Backpressure処理が遅くても録音はローカルバッファへ継続。
03 / TypeScript boundaries

交換できる境界

アプリ本体はプロバイダーSDKやOS APIを直接知りません。型付きポートを介して差し替えます。

推奨モノレポ構成

同じ型を共有しつつ、ブラウザ・サーバー・ワーカーの実行境界は分けます。

apps/web録音、IndexedDB、字幕UI、WebSocket client
apps/serverHTTP/WS、Session、Media ingest、認証
apps/workerASR、翻訳、分析ジョブ（MVPではserver同居可）
packages/contractsDTO、イベント、JSON Schema、エラーコード
packages/domain状態遷移、ID、順序、冪等性ルール
packages/providersASR / Translator / Storage adapters
packages/workflows分析ユースケースと WorkflowRuntime port
packages/pi-durable任意導入。実験APIを隔離するadapter package

中核ポート

具象実装ではなく、アプリケーションが所有するinterfaceへ依存します。

SpeechRecognizerprovider port
interface SpeechRecognizer {
  transcribe(input: AudioRange,
    signal: AbortSignal):
    AsyncIterable<AsrEvent>;
}
Translatorprovider port
interface Translator {
  translate(input: FinalUtterance,
    target: Language):
    Promise<TranslationResult>;
}
WorkflowRuntimeoptional durability
interface WorkflowRuntime {
  start<T>(job: WorkflowJob<T>):
    Promise<WorkflowHandle>;
  resume(id: WorkflowId):
    Promise<WorkflowHandle>;
}
04 / Optional durability

pi durable の置き場所

コア処理の必須依存にはしません。長時間のLLM分析が必要になった時だけ、WorkflowRuntimeの実装として追加します。

Optional integration

AIワークフローだけを耐久化

分析の会話・モデルターン・ツール呼び出し・独自状態を保存し、プロセス停止後に再開します。音声と字幕の正本は、引き続きアプリケーションDBが持ちます。

責務の線引き

✓使う: 数分以上の分析、複数ツール、途中再開が必要な処理
✓使う: LLMの会話・ターン・ツール結果の耐久化
✓隔離: 専用packageと専用SQLite、バージョン固定
×使わない: 音声チャンクの高速取り込み経路
×使わない: Session / Utterance の正本DB
×使わない: ASRや翻訳を止める同期依存
注意: @earendil-works/pi-durable は Experimental。adapter外へ型を漏らさず、更新時は契約テストで保護します。

06 / Failure isolation

壊れた時のふるまい

障害を一つの大きな「失敗」にせず、失敗した段階だけを止めて再実行可能にします。

Failure
Behavior
User-visible result
ネットワーク切断
IndexedDBへ録音継続。再接続後に未ACK seqを再送。
「オフライン保存中」を表示。復帰後に自動追いつき。
ASR停止
音声保存は継続。未処理rangeをjobとして保持。
字幕は遅延するが、録音は失われない。
翻訳API停止
確定原文を保存し、翻訳jobだけ指数バックオフ。
原文を先に表示し、翻訳は後から追加。
分析停止
主経路に影響なし。必要ならpi durableから再開。
要約だけ「処理待ち」。字幕と翻訳は継続。
プロセス再起動
DBのlease切れjobと処理済みcursorから復元。
重複せず再開。進捗状態をUIへ再同期。
07 / Deployment choices

同じ設計で3つの配置

Windows-first 推奨

ブラウザUIとローカルNodeサービスを localhost で動かします。導入が簡単で、音声を端末内に置けます。

  • Chrome / Edge を最初の対象にする
  • SQLite + ローカル音声ファイル
  • ASRはローカルfaster-whisper sidecar

08 / Delivery plan

小さく縦に作る

最初からすべてをリアルタイム化せず、保存と再処理が正しい縦断経路を先に完成させます。

PHASE 01

File vertical slice

録音済みファイルから字幕・翻訳までを通す。

  • Domain model + SQLite
  • ASR / Translator ports
  • 確定発話と履歴UI
PHASE 02

Reliable live capture

マイク録音、ACK、再送、リアルタイム表示。

  • IndexedDB buffer
  • WebSocket resume
  • 暫定 / 確定ASR
PHASE 03

Advanced workflows

分析、OS固有音声、クラウド配置を必要順に追加。

  • pi durable adapter
  • Native audio bridge
  • PostgreSQL / Object Storage
