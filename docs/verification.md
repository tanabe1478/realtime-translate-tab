# 受入確認：YouTube・話題／用語集・翻訳プロバイダー

## 自動確認の範囲

```sh
pnpm typecheck
pnpm test
pnpm test:e2e
```

- 入力検証、上限、JSON出力検証、未出現の新規用語の除外
- YouTube固定ホストのみへの動画情報取得（任意URLをサーバーから取得しない）
- 認証未設定・生成失敗時に既存の用語集を保持し、再試行できること（別プロバイダーへのフォールバックではない）
- OpenAI / Goの明示選択、既存OpenAI資格情報の保持、キー未設定・認証失敗時の非切り替え
- Goの実SDKによるリクエストの送信先・Bearer認証・固有User-Agent・安定した会話ID（HTTPのみ代替）
- 401 / 403 / 429 / サーバーエラー、タイムアウト、出力上限・不正JSON・空応答、秘密情報を含めないエラー表示
- UIで接続先・モデル・OAuth/APIキーの区別と、Go未設定時の適切な案内
- Ubuntu標準のPython 3.14を避けた対応版の選択、既存仮想環境と明示指定の扱い
- APIポート変更時の開発用HTTP/WebSocketプロキシの追従
- 形式不正時のみ同モデル・同期限で1回再生成し、認証・利用枠・通信エラーは再試行しないこと
- 二重生成防止、更新間隔、生成途中の手動保存の優先、楽観ロック
- 古いDBのマイグレーション、再オープン時の永続性、動画・言語の分離
- HTTP/WebSocketからASR・翻訳への用語反映と、最終音声の到着を待つ完了判定
- ブラウザでの自動生成表示、原文からの更新、手動編集・保存・再読込・自動復帰
- 動画・字幕の同時表示、小さい画面の表示
- セッションの直接リンクからの復元、ブラウザ内の復元情報がない場合の表示、新規録音時のURL更新
- 一時的な復元API障害でセッションIDを消さず、再読み込みで回復すること

E2Eは専用の一時DBを使います。音声共有の許可・デバイス、Whisper、翻訳モデル、YouTube iframeの内容は代替です。音声Worklet、WAV化、IndexedDB、実HTTP/WebSocket、SQLite、生成サービス、UIは実装を通します。実動画の音声認識精度や翻訳品質を測ったテストではありません。

公開音声＋実Whisper＋実Go APIで別途確認した結果は[local-verification.md](local-verification.md)に記録しています。実際のYouTubeタブ音声共有は、その確認とは別です。

## 実機での確認（利用者のブラウザ・認証が必要）

1. Node.js 24、pnpm 10、Python 3.10〜3.12を用意する。UbuntuでPython 3.14などが標準の場合も、Whisper用には対応版を別途用意する。
2. READMEに従って`.env`とWhisperを設定する。`TRANSLATION_PROVIDER=openai`なら`pnpm auth:openai`、`opencode-go`ならローカルの`.env`へ`OPENCODE_API_KEY`を設定する。Goの用途・契約上の利用可否は事前に確認する。Pi本体のログインは、このアプリ専用の認証には自動流用しない。
3. `pnpm dev:local`を実行し、`http://127.0.0.1:5173`をChrome/Edgeで開く。左側の接続先・モデル・認証方式が設定と一致することを確認する。「設定あり」はキー・資格情報の設定があるという意味で、認証成功や利用枠は保証しない。
4. `https://www.youtube.com/watch?v=HDdbU10r7Js`を入力して「動画を表示」を押す。
5. 「話題・用語集」が生成中→生成済みに変わることを確認する。タイトルは「State of Agentic Coding #11 with Geoff, Armin, and Ben」、チャンネル名は「Armin Ronacher」。
6. パネルを開き、根拠が動画情報だけであること、動画の結論を勝手に要約していないことを確認する。Piがタイトルに出ない場合、初期用語集にPiがなくても異常ではない。
7. 「翻訳を開始」を押し、**このアプリのタブ**と**タブの音声**を共有する。プレーヤーを再生する。音が聞こえること、音量メーターが動くこと、5秒以降に原文、発話確定後に訳文が出ることを確認する。
8. 発言に製品名や用語が登場すると、用語集の根拠が実際の発言に変わり、候補が増えることを確認する。生成待ちで字幕が止まらないことも確認する。
9. 製品名の誤認識があれば「確認・編集」で原語・訳語を直し、「保存して固定」。以後の認識・翻訳へ反映され、自動更新に上書きされないことを確認する。
10. 録音を停止し、未送信0→残り処理→完了となることを確認する。再読み込み後も動画・セッション・手動用語集が復元されることを確認する。

## プロバイダー切り替えと実API確認

1. Goの利用条件を満たすことを提供元へ確認したうえで、Goの設定で短い入力の翻訳と用語集生成を試す。キーを画面・ログ・Issueへ記録しない。
2. 403なら用途・モデル権限を確認する。コーディングエージェントを装う、入力を水増しする、制限を回避する、といった対応はしない。
3. 401・429でもOpenAIへ自動切り替えせず、元の音声・原文・用語集が残ることを確認する。
4. 録音停止・未送信0・処理完了後にサーバーを停止し、`.env`を`TRANSLATION_PROVIDER=openai`へ変更して再起動する。保存済みOAuth認証がそのまま使え、左側の表示もOAuthになることを確認する。期限切れ等なら再ログインする。
5. 逆方向の切り替えでも`data/auth.json`が消えないことを確認する。過去の字幕・手動用語集も保持する。

切り替えはサーバー全体と再起動時の未完了処理に適用します。既存の用語集は共通キャッシュなので、新しいプロバイダーで生成を確認したい場合は「再生成」を押してください。Goの利用可否・日本語品質・応答速度は、HTTP代替テストだけでは検証できません。

## 品質比較

同じ30〜120秒の区間を、新しいセッションで比較する。音声言語は英語に固定すると、言語検出の影響を減らせます。

- A：話題を空、用語を0件にして手動固定
- B：自動生成に戻した状態
- C：自動生成＋固有名詞の手動訂正

比較する項目は、文字起こしの固有名詞、専門用語の訳語・表記揺れ、意味の取り違え、発言にない補完、字幕の遅延です。直近の発話文脈はA/B/Cともに同じ機能を利用します。自動生成の内容が正解とは限らないため、人が原音と照合してください。

## 失敗時

- **生成できない**：選択中プロバイダーの認証、ネットワーク、モデル利用可能性・利用条件を確認。サーバー再起動後に「再生成」。生成エラーの詳細に認証トークンを出さない設計です。
- **共有したが音量メーターが動かない**：共有対象がアプリのタブか、音声共有がオンか、プレーヤーが再生・ミュート解除されているか確認。ブラウザやOSによる制限もあります。画面全体・ウィンドウ共有への自動フォールバックはしません。
- **生成に失敗するが原文は出る**：音声処理は独立して動作しています。手動用語集または既存の文脈で続行できます。選択中プロバイダーの認証未設定なら翻訳自体も待機します。
- **手動保存が競合する**：下書きは残ります。最新の内容を確認したうえで再保存するか、キャンセルして編集し直してください。

実機確認が済むまでは「特定の動画で品質改善を確認済み」「Ubuntuで実タブ音声まで確認済み」とは扱わないでください。
